# Phase F: ownership and live-scene adapters

Live Ship Store, Hangar, Insurance, Fit, loadout and repair UI requests now submit trusted native ownership commands. The worker receives copied ownership records, prepared hull/component data, dealer context, prices, stock IDs, missile requirements and receipts. Catalog/ship construction and Actor/Ship/Hangar access remain on the game thread. The prepared data path does not resolve legacy design registries on the worker. Existing insurance quote helpers are pure static arithmetic; no subsystem instance or UObject is passed to or accessed by the calculation.

Ownership results merge only hangar, rental, local equipment, skin-license and assigned/selected-hull fields. They never overwrite rank, mission history, skills, time or player preferences. Acceptance compares the original ownership read set, economic revision and account/session token. Fees and included taxes retain existing SSW formulas. Hull offers retain their physical identity; the last serviceable owned fighter remains protected. Rentals retain NPC title and return to dealer stock, not replenished combat squadron slots.

Carrier reserve transfers, component installation, live loadout changes and repair projection execute in the game-thread save adapter. Failed saves restore native runtime state and player/economic state together. Player launch waits while a transaction is pending. Loadout-template rollback validates scene/mission lifetime, including a closed widget. The standard repair buttons use saved requests and completion feedback.

Confirmed destruction creates a critical native loss command. Scene unload and economy shutdown drain this command before invalidating its scene/account, cancelling ordinary unstarted requests at that transition barrier. This wait is a transition-only barrier, not a flight tick. Claims use a distinct request receipt, avoiding a collision with older purchase receipts that used the hull identity. Cargo/ownership loss, payout and rental liability remain one saved result. Unrelated ships and career progress are retained.

Six focused actual-worker tests cover ownership isolation, stale read sets, save rollback, preserved career fields, serialized purchase/sale, last-fighter protection, rental/return, policy fees, lifetime loss payout, replay protection, component inventory, finite missile stores and lost-cargo rollback. Final build and suite results are in Phase-F-Execution-Domains.md. The automated boundary does not replace the user's packaged carrier/fitting presentation check.

Remaining financial UI migration: skill-book purchases and paid instant training. Initial magazine provisioning, AI replenishment, mission/progression adapters and live flight/combat/AI remain serialized live-scene bridges; they invalidate stale economic snapshots. Original Phase F begins the simulation migration incrementally; the dedicated simulation broad phase is the implemented first step, not a fully moved flight loop.
